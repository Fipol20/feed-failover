# feed-failover

Два источника кадров, один экран. Пока primary свежий, показываем его. Если он замолчал дольше порога — backup. Если молчат оба — `NO_DATA`.

Кадр сам придуманный: `seq`, `timestamp_ms` и пара чисел. Сокетов и протокола обмена тут нет, только правило переключения.

Свежесть — это `now - timestamp_ms`. Часы в библиотеку не зашиты, время передаётся аргументом, порог тоже задаётся снаружи. У primary и backup разные `seq`, при переключении они не склеиваются. Повтор того же `seq` с того же источника на экран второй раз не попадает. Очередь на вывод короткая: обычный кадр не выкидывает из неё alert.

```bash
cmake -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Демо крутит 24 тика и после 12-го перестаёт кормить primary. Backup в это время живёт своей нумерацией.

```bash
./build/feed_demo
```

Сборка Visual Studio кладёт бинарник в `build/Release/feed_demo.exe`.

В выводе сначала `PRIMARY`, потом несколько строк с `(hold)` — последний кадр ещё не протух, нового нет — затем `BACKUP`.

Если живы оба источника, backup не показывается и с primary не сравнивается.
